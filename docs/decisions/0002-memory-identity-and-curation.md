# ADR-0002：稳定用户身份与可审计记忆整理

- 状态：Accepted
- 日期：2026-08-24
- 决策者：项目所有者
- 关联：Issue #36

## 背景

当前记忆萃取把“我”“我的”统一改写成“用户”，同时把“林夕”这类姓名抽取为独立的“称呼别名”实体。由于去重按实体类型限制候选，系统会得到“用户”和“林夕”两个节点；检索命中“林夕”时也不会自动回到用户本人的其他事实。

人工审查接口可以确认、修改或删除实体，但不能表达“林夕就是我”“以后叫我小夕”“撤销刚才的记忆修改”等完整意图。后续需要让记忆系统具备受约束的 Agent 式整理能力，同时保护来源、历史和用户数据。

## 决策

### 1. 用户本人使用稳定身份锚点

- 每个用户只有一个内部稳定的 self 身份，内部标识不随姓名变化。
- 展示名称、当前偏好称呼和历史别名是该身份的属性或带来源的身份声明，不通过新的“称呼别名”实体表达。
- “我”“用户”“林夕”“小夕”等名称在明确指向用户本人时解析到同一个 self 身份。
- “小说中的林夕”“我的同事林夕”等存在角色或关系限定的表达不能自动绑定到 self；无法判断时进入待确认状态。

### 2. 实体解析先于图谱写入

记忆写入顺序固定为：

```text
原文 → 陈述抽取 → 身份/实体解析 → 候选去重 → 图谱写入 → 规则校验
```

LLM 可以提出候选身份和关系，但不能直接执行 Cypher，也不能绕过用户隔离、来源校验和风险策略写入图谱。

### 3. 自然语言整理采用“计划—预览—确认—执行—撤销”

记忆整理 Agent 只输出受控的结构化操作计划，例如：

- `set_self_display_name`
- `add_self_alias`
- `remove_self_alias`
- `merge_entities`
- `correct_relation`
- `invalidate_fact`
- `forget_source`

补充低风险别名和确认已有事实可以自动执行；合并人物、删除来源、覆盖事实和处理歧义必须展示影响范围并要求确认。每次操作都要写入审计记录，并提供撤销或补偿路径。

### 4. 来源和历史优先于“看起来干净的图”

- 原始 Dialogue、Chunk、Statement 和操作记录不能因为实体合并而丢失。
- 关系支持多条证据和时间有效性，不能用最后一次写入覆盖全部来源。
- 删除优先采用失效/隐藏；真正物理删除必须是明确的用户操作，并说明影响范围。

### 5. 图谱展示区分语义层与溯源层

默认视图展示规范实体、关系和身份别名；对话、片段、陈述和事件作为点击后的证据与溯源展开，避免用户把不同层级的溯源节点误认为重复实体。

## 风险分级

| 操作 | 默认策略 |
| --- | --- |
| 添加明确的用户别名 | 自动执行并记录来源 |
| 确认已有 self 关系 | 自动执行或轻量确认 |
| 纠正实体描述 | 预览后确认 |
| 合并两个具体人物 | 必须确认 |
| 删除/失效事实或来源 | 必须确认并保留撤销信息 |
| 无法判断是否指向用户本人 | 不自动修改，进入待审查 |

## 非目标

- 本 ADR 不授权立即迁移或删除现有 Neo4j 数据。
- 本 ADR 不要求把所有记忆功能重写为微服务。
- 本 ADR 不允许为了减少节点数量而牺牲陈述来源和历史事实。

## 实施顺序

1. 建立身份场景回归集和当前行为基线。
2. 增加 self 身份锚点、别名解析和逻辑唯一性。
3. 修复别名召回、关系方向、陈述/事件检索与证据保留。
4. 增加结构化记忆整理 Agent、审计和撤销。
5. 对旧图谱执行只读扫描、dry-run 迁移和受控回填。
