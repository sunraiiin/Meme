# Meme 核心演示流程回归清单

这份清单用于本地回归和面试演示，覆盖 Meme 的主叙事：知识库、可解释对话、长期记忆和调用追踪。
它不自动注册账号、不上传个人资料、不删除数据；需要真实模型调用的步骤由操作者手动确认。

## 0. 前置条件

- Docker Desktop、WSL 2、Node.js、npm、uv 已可用。
- 根目录 `.env` 已由 `.env.example` 复制并填入本地开发密钥。
- 已准备一个专用演示账号，不使用真实个人敏感资料。
- 已在“模型配置”中配置对话模型、Embedding 模型；需要图片演示时再配置多模态模型。

启动服务：

```powershell
docker compose config
docker compose up -d --build
```

## 1. 自动检查

这一步不创建业务数据，作为每次合并前的最低门槛：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify-local-baseline.ps1
```

预期结果：

- 后端 Ruff 通过。
- 前端 ESLint 通过；已有 Hook warning 不应升级为 error。
- 前端生产构建成功。
- Compose 配置有效，API `/api/hello` 和 `/api/health` 可访问。
- `/api/health` 中 PostgreSQL、Elasticsearch、Neo4j、Redis 均为 `true`。

后端记忆和图谱相关回归也可单独复核：

```powershell
Set-Location api
uv run python -m unittest discover -s tests -p 'test_*.py'
uv run ruff check .
Set-Location ..
```

## 2. 面试演示主流程

### A. 登录与模型配置

1. 使用演示账号登录。
2. 在模型配置中测试对话模型和 Embedding 模型连接。
3. 需要图片理解时，再测试多模态模型连接。

预期：登录成功，模型测试返回成功；密钥不出现在页面、日志或接口响应中。

### B. 知识库入库与引用

1. 创建一个演示知识库。
2. 上传一份无敏感信息的 Markdown/PDF 文档。
3. 等待状态从“解析中”变为“完成”。
4. 在对话中询问文档中的明确事实。

预期：回答包含可定位的知识库引用；引用失败时先检查文档状态，再检查 `comet-worker` 日志。

### C. 单人流式对话

1. 新建单人会话。
2. 发送一个需要知识库检索的问题。
3. 观察回答逐步流式返回。

预期：SSE 流不中断，回答完成后显示引用、工具调用或检索依据（若本轮命中）。

### D. 长期记忆与图谱

使用非敏感的演示信息，例如：

> 我叫林舟，正在准备 AI 应用工程岗位面试；我家的宠物叫多多。

1. 让系统记住这段信息。
2. 查看记忆列表、实体和关系图谱。
3. 搜索“林舟”和“多多”。
4. 查看记忆来源或关系证据。
5. 在图谱页先使用“聚焦视图”查看本人节点及一跳关系，再切换“全景视图”查看完整的实体、事件和来源层级。
6. 分别点击实体、陈述、片段和对话节点，确认详情面板能显示完整文本和来源信息。

预期：

- “林舟”作为 canonical self，只有一个活动本人节点。
- “多多”保持独立，不会被误合并为本人。
- 记忆、关系和事件能回到来源陈述。
- 图谱中旧的逻辑失效节点只作为审计信息，不参与新检索。
- “合并同类实体”只处理同名同类型的有效实体；相同文字出现在不同层级时属于不同的来源节点，不应直接删除。

### E. 跨会话主动召回

1. 新建一个会话，不重复上一段完整自我介绍。
2. 提问与职业目标或项目背景有关的问题。

预期：回答能在有依据时使用长期记忆，并能区分知识库资料与用户记忆；不应凭空编造未存储信息。

### F. Trace 与质量信息

1. 打开调用追踪，查看刚才的对话记录。
2. 检查模型、检索、工具调用、Token 和成本信息。
3. 若演示深度研究，再查看报告和导出能力；Verifier 作为内部质量步骤，不要求单独导航入口。

预期：Trace 能解释“调用了什么、为什么命中、消耗多少”；默认产品表面不出现 Loop 健康度卡片、技能和语音入口。

## 3. 失败定位顺序

| 现象 | 先检查 | 再检查 |
| --- | --- | --- |
| 页面打不开 | `docker compose ps`、Web 容器日志 | API `/api/health` |
| 登录 502/失败 | API 容器日志、PostgreSQL 健康状态 | `.env` 与 JWT 配置 |
| 文档一直解析中/失败 | 文档状态接口、`comet-worker` 日志 | 文件格式、Embedding 配置、ES 健康状态 |
| 对话无流式输出 | API 日志、浏览器 Network 的 SSE 请求 | 对话模型连接、Redis 状态 |
| 记忆未出现 | 记忆接口和 worker 日志 | Neo4j 健康状态、抽取模型配置 |
| Trace 缺失 | Trace 页面请求和 API 日志 | 异步落库器、PostgreSQL 状态 |

建议保留以下证据，不提交真实数据：

- 当前 `main` commit。
