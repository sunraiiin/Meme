# 功能边界决策提案

> 状态：Draft，等待用户确认
>
> 关联 Issue：#1
>
> 本文只定义建议，不授权删除代码或数据。

## 1. 建议的产品主线

Meme 建议聚焦为：

> 一个可解释、可评测的个人 AI 知识库与长期记忆助手。

面试演示主流程控制在十分钟内：

1. 用户登录并完成模型配置。
2. 上传一份文档，后台解析并建立混合检索索引。
3. 在对话中提问，Agent 调用知识库并返回可追溯引用。
4. 让系统记住一段个人信息，展示实体、关系和事件图谱。
5. 开启新会话，展示主动记忆召回。
6. 查看一次调用的 Trace、Token、成本和评测结果。

## 2. 决策原则

- 核心功能必须服务于同一条产品叙事。
- 优先保留能体现个人工程能力、可解释性和质量保障的模块。
- 首次演示应能稳定启动，不要求观众理解全部基础设施。
- 删除前先隐藏并验证依赖，数据库变更单独迁移。
- upstream 原代码与 Meme 新增贡献应能在 Git 历史和文档中区分。
- 在授权未明确前保持仓库私有，不对复制代码追加自定义开源许可证。

## 3. 功能分类提案

### A. 保留并重点重构

| 功能 | 建议 | 原因 | 首轮目标 |
| --- | --- | --- | --- |
| 账号与用户隔离 | 保留 | 展示完整 Web 应用的安全与多租户意识 | 简化注册登录流程，补鉴权测试 |
| 模型配置与密钥加密 | 保留 | 支撑多 Provider，体现安全存储 | 增加首次使用引导和默认配置校验 |
| 知识库与文档入库 | 保留 | 产品主线入口 | 统一状态机、错误提示和重试 |
| 混合检索与引用 | 保留 | RAG 的核心技术价值 | 建立可重复评测和引用准确性指标 |
| 单人流式对话 | 保留 | 最主要用户交互 | 降低 ChatService 耦合，明确用例边界 |
| 个人记忆与图谱 | 保留 | 与普通 RAG 项目的主要差异点 | 明确数据模型、召回策略和可删除性 |
| 主动召回与跨会话上下文 | 保留 | 展示长期记忆价值 | 增加召回解释和命中来源 |
| Trace、Token 与成本 | 保留 | 面试中可解释工程过程 | 统一对话和检索链路追踪 |
| 离线评测 | 保留 | 证明效果而非只展示界面 | 固化小型、可本地复现的基准集 |

### B. 重新设计后保留

| 功能 | 当前问题 | 建议方向 |
| --- | --- | --- |
| 首页 Dashboard | 同时混合统计、每日回顾、主动关心和任务简报 | 改为“导入状态、最近对话、记忆概览、系统健康”四块 |
| Agent 配置 | 人格、工具、真人模式和跨会话开关集中，认知负担高 | 划分为基础设置与高级设置 |
| Skills | 能力强但与面试主线关系不直接 | 首版只保留少量内置模板，自定义能力进入高级入口 |
| MCP | 配置成本高，且容易分散演示焦点 | 作为可选扩展能力，不进入首次使用流程 |
| 图片知识 | 同时包含图库、OCR、视觉描述和聊天附件 | 首版保留聊天附件和知识入库，图库管理后置 |
| 全局搜索 | 文档、图片、记忆并排但语义不同 | 统一结果模型，并明确来源、分数和跳转行为 |
| 图谱页面 | 信息丰富但可能难解释记忆为何命中 | 增加来源、时间和召回理由视图 |

### C. 首版隐藏，代码暂时保留

| 功能 | 隐藏原因 | 重新评估条件 |
| --- | --- | --- |
| 深度研究 | 流程重、依赖联网搜索和多次 LLM 调用 | 核心 RAG/Memory 演示稳定后作为第二案例 |
| Verifier Loop | 主要服务深度研究，目前不属于首条主线 | 研究模块重新开放，或迁移为通用回答评测 |
| 收藏、复杂标签管理 | 属于内容管理增强项 | 核心流程完成后按真实使用反馈决定 |
| 对话和报告公开分享 | 涉及公开 Token、安全和内容快照 | 计划部署公开 Demo 时再评估 |
| 报告 Word 导出 | 依赖研究报告 | 研究模块重新开放时恢复入口 |

“隐藏”表示从主导航和首次使用流程移除，不删除 API、数据表或历史迁移。

### D. 候选删除，必须再次确认

| 功能 | 建议删除原因 | 删除前必须处理 |
| --- | --- | --- |
| 情绪分析 | 与知识库和长期记忆主线关系较弱，会增加每轮对话后台任务 | ChatService 投递、首页统计、模型调用、表和任务 |
| 音乐库与情绪推荐 | 独立产品方向，包含文件、播放、咪咕和推荐逻辑 | 页面、全局播放器、API、存储文件、任务和表 |
| 多 Agent 群聊 | 代码量和实时状态较大，与个人助手主线冲突 | 会话模型共用字段、成员表、SSE、邀请入口 |
| 定时 Agent 任务 | 依赖 Beat、研究和通知，部署复杂 | Celery beat、任务表、研究队列和首页简报 |
| 多渠道通知 | 主要为定时任务服务，并包含外部 Webhook 风险 | 加密配置、SSRF 防护、渠道表和前端设置 |

候选删除项在用户确认前只允许做依赖分析，不允许删除代码、表、迁移或用户数据。

隐藏入口暂不出现在主导航，但可以保留受控路由，方便逐项验证后再决定永久删除。

## 5. 第一轮需要用户确认的决策

- 是否接受“知识库 + 长期记忆 + 可解释评测”作为唯一主线。
- 是否确认情绪、音乐、多 Agent 群聊、定时任务和通知进入候选删除。
- 深度研究是作为后续高级案例保留，还是也进入永久删除候选。
- 图片能力是保留完整图库，还是只保留知识入库与聊天附件。
- 项目最终是否计划公开；公开前必须先解决 upstream 授权问题。

## 6. 完成定义

本文从 `Draft` 变为 `Accepted` 前，不开始破坏性重构。接受后，每个删除或重设计模块单独建立 Issue，至少包含：

- 用户可见变化。
- 前后端和数据依赖范围。
- 迁移与回滚方案。
- 测试与验收方法。
- 面试展示价值和个人贡献说明。
